# ADR-0001：chief 是非 LLM 的工程决策树

- 状态：已接受
- 日期：2026-11-16

## 背景
主流 personal agent（如 OpenMausBot 的 Chief of Staff）用 LLM 作协调者，常见问题：自己动手而不委派、转述走样、上下文随任务数膨胀、行为不可预测难复盘。

## 决策
chief 是声明式决策树的执行器。协调者只做几类事：派发新任务、咨询进度、操作/回复已有任务、回答 worker 的提问、澄清、下沉慢脑。
LLM 只允许出现在树中显式声明的节点：`classify`（Jev）、`slow`（慢脑 bot）、`rewrite`（回包改写 fork）。chief 自身只输出模板文本。

## 理由
- 把明确行为工程化，减少协调者"自作主张"。
- 每次决策可记录、可回放、可测试、可评测。
- chief 不持有长上下文，任务再多也不退化。
- 快脑处理不了时下沉慢脑是合理机制，但下沉本身必须是树的一环（用户在讨论中明确放开）。

## 后果
- 需要高质量的分类器与决策日志驱动的阈值调优。
- 复杂/复合请求的处理质量取决于慢脑 bot。
- 任务拆解不由 chief 做，交给 worker 自身。
