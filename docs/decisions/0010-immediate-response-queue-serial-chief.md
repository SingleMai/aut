# ADR-0010：即时响应 + 排队；chief 串行处理

- 状态：已接受
- 日期：2026-11-16

## 背景
曾提议"等用户停顿约 2 秒再合并处理"，被否决：及时响应更重要。OpenMausBot 同样没有输入停顿合并，只在队列排出时合并（`server/admission.ts`，120s / 30 条）。

## 决策
- 每条消息立即进入 chief；目标 session 忙时由决策树语义选择 queue / steer / restart。
- 只在投递队列排出时合并已排队的消息。
- main thread 消息由 chief 串行处理（全局唯一排序点），session 执行并发。

## 理由
即时反馈；串行保证后一条消息能引用前一条刚创建的任务；Jev 单次约 200ms，串行几乎无感。

## 后果
chief 处理单条消息的延迟必须保持在亚秒级；慢节点（slow/rewrite）一律异步，不得阻塞 chief 队列。
