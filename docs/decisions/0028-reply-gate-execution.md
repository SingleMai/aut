# ADR 0028：回包树的隔离执行与失败收尾

- 状态：已采纳（ADR-0007 的实现细化）
- 日期：2026-11-16

## 背景

回包树需要对当前 worker 做隔离改写，同时保留原报告与当前任务所有权。临时改写的
进程故障、意外中断和未给出报告都不能被误判为成功回复。

## 决策

- 长度状态预计算 Unicode 码点数与空白分词数；含汉字的混合文本用 200 字符门槛，
  其余文本用 120 词门槛。长度与可读性阈值、最多两次改写都放在树配置。
- 不合格或分类器不可用均走显式 rewrite 节点，重写结果重新过门槛。
  每次从原 worker 新建 fork，尝试结束即关闭该 fork 的 Scope；不支持 fork 时开新 session，
  只提供固定改写指令和原报告，不注入主会话或 bot soul。原 worker 不接收改写 turn。
- 改写子回合由独立 Scope 管理，观察真正的成功完成事件，不依赖文字标记。
  进程退出、中断、失败、空报告或改写要求额外用户输入时，取消该次内部改写并进入树的
  onError 截断路径；绝不向 question 回填空答案或虚构答案。它不会把原 worker 变成等待状态。
  内部改写事件持久化供审计，失败原因写入 gate 日志的执行结果。
- 每次改写设有可配置执行超时；超时只取消内部改写，不中断原 session。
- 截断基于最近有效文本，包含“详情见任务面板”，最终文本不超过 200 码点和 120 词。
  完整原文始终由原始成功完成事件与 Task.lastReport.full 保留。
- Gate 只返回已检查文本与尝试次数；SessionManager 核对当前执行所有权后，事务写入
  reply、lastReport 和 gate.done，旧回合或取消后的结果不得发布。

## 后果

worker、慢脑和 deep ask 使用同一 gate。分类器故障不会让原始长报告绕过门槛；
额外模型工作只出现在树声明的 rewrite 节点，主会话的 Chief Fiber 不等待它。
