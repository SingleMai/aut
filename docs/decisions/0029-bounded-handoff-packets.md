# ADR-0029：受预算约束的交接包

- 状态：已接受
- 日期：2026-11-16

## 背景

主会话不能默认全量进入 worker。handoff-prune 必须显式批量分类、保留完整决策日志，
并且在分类失败时仍限制上下文。现有 AST 的 take 不能表达累计成本，交接片段的 relevance 也不能伪造。

## 决策

1. 候选为本次最早请求之前最近20条已持久化主会话消息，排除本次全部请求；不会纳入之后到达的消息。
   合并请求完整保留并按主会话入库顺序渲染；时间戳只作显示，时钟回拨或同时间戳不改变入站顺序。
   当前MVP请求必须引用持久化的user/text消息，不能将bot或chief输出冒充用户原话。
   new/send 共用剪枝管道；send 的任务头明确这是当前任务的后续请求。
2. handoff-prune 数据树静态声明最多20条条件 noul 问题，同一次调用；英文问题显式引用 candidate_0 等候选标识。
   概率至少0.5的候选按概率降序稳定排列，预算选择后恢复原时间顺序。空候选不调用分类器。
3. AST 新增通用 budget：from为数组，by为成本字段路径，limit为非负安全整数表达式。
   按输入顺序贪心保留可容纳的完整项，跳过超预算项后继续检查其余项。成本必须是非负安全整数，
   缺字段、负数、非有限数和非法limit产生类型化解释错误；零预算返回空数组。
4. 默认2000预算只约束相关片段，包括消息ID、时间、作者与分隔符的渲染成本。
   以UTF-8字节数作为保守token上界，无额外tokenizer依赖；这可能比实际模型token计数保守。
   用户原话不截断，任务头与工具提示单独保留，不声称整个包一定小于2000 tokens。
5. 分类器失败走树内显式降级：只取最近2条候选，再应用相同预算；不额外做语义判断。
   HandoffPacket.excerpts.relevance 改为可选：正常分类填写真实noul，降级省略，并以决策日志路径标明原因。
   降级包只保留固定任务头、原话、预算内最近2条与工具提示，不再展开相关任务或下沉摘要。
6. 纯模板渲染任务头、全部用户原话、相关片段、相关task引用与MCP工具提示；不复制任务完整报告。
   下沉慢脑时，仅依据已有决策日志生成有界摘要；没有树外模型调用。引用提供ID，细节由read_main_thread/get_task按需拉取。
7. HandoffBuilder 为必需 Service，依赖 Store、ConfigStore、DecisionTree、DecisionLog。树输出后校验候选ID与概率，
   包和TurnInput均经Schema校验；成功/失败完成对应剪枝日志，不把执行失败伪报成功。

## 后果与验收

同步协议、树配置与fixture；覆盖0.5边界、稳定排序、成本边界、超大项、零预算、最近20、请求排除、
分类失败最近2、无伪造概率、新建/后续多消息模板和慢脑摘要。预算只影响上下文，不删除用户请求。
