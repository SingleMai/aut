# ADR-0043 主会话按引用读取 SQLite 记录

发布前存储格式现行规则见 [ADR-0048](0048-pre-release-data-baseline.md)。

- 状态：已接受
- 日期：2026-11-18

## 背景

每次入站去重都解码全部决策日志。问题卡的查找和收尾也反复遍历主会话，排队较久的交接还会从最新消息向前翻页。这些读取占用所有 session 共用的 SQLite 事务，开销随无关历史增长。

## 决策

沿用 ADR-0018 的六张表、事务边界与 Effect Schema。SQLite 第二版在原子迁移中为决策日志的事件引用、用户事件、卡片 ID、问题引用和未关闭请求建立索引。入站恢复按入库顺序读取用户事件，每个事件使用最近登记的关联决策。交接按用户消息 ID 读取原文，按入库顺序确定最早请求，再向前取候选窗口。

## 理由

原生问题卡和 chief 生成的题组入口都可以指向同一 request。按该引用查找能同时定位两者，也适用于没有顶层 taskId 的既有卡片。

## 后果

首次打开第一版数据库时 SQLite 为已有记录建立索引，耗时取决于历史规模。业务记录继续沿用原有 JSON 和序号，查询结果仍经对应 Schema 校验。数据库版本与查询入口见 `docs/storage.md`。
