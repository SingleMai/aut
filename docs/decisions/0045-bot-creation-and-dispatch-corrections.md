# ADR-0045 主会话建 Bot 与派发纠正

状态为已接受，2026-11-18。

## 背景

用户确认了两种建 Bot 的入口。用户可以手动配置，也可以在主会话委托 Agent 创建。用户还需要纠正已派给错误 Bot 的工作。原有澄清降级有时会用最近任务替换明确引用，自定义 Bot 描述则会直接出现在 Jev 判据里。

## 决策与理由

- 普通工作 Agent 和慢脑均可经会话 MCP 的 `create_bot` 创建普通 Bot。daemon 的同一配置服务处理工具与桌面表单的创建请求。工具可沿用调用者的模型选择与工作目录，新 Bot 默认使用空的自定义 MCP 列表。调用成功返回持久化的 Bot ID 和名称。
- 主会话上的用户派发确认提供显式改投和撤销。改投使用原用户消息 ID 为目标 Bot 新建独立任务，原任务保留，可单独取消。撤销调用原任务的取消操作。在登记操作的同一个 SQLite 事务里将纠正及其决策 ID 记入原日志，重复提交只能登记一次。
- Jev 从 state 读取原语言的 Bot 专长、任务摘要和问题。英文判据通过候选位置或键引用这些数据，正式路由与路由试验采用同一个 Bot 选择题。分类不可用时，引用回复的继续选项使用被引用任务。

## 后果

两种创建入口共享 ID 唯一、实例引用与系统身份约束。历史 Bot 配置可直接参与分类。原派发确认可根据已有决策日志和任务展示纠正操作。每次改投仍遵守一个任务绑定一个 Bot 的约定。
