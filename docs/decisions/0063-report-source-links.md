# ADR-0063：回包来源链接与摘要分离

- 状态：已接受
- 日期：2026-11-23

## 背景

MCP 搜索验收中，原报告包含完整来源，回包门槛的最后截断却把 URL 截成了无效地址。用户要求修复主会话的来源展示，同时保留既定的简洁回包规则。

## 决策

1. `MainThreadMessage` 与 `MainThreadExcerpt` 增加可选 `sources`，元素为 `{ url, label }`。它是原始成功报告的引用元数据，正文仍完整经过现有 reply-gate；不新增模型调用或决策分支，不改变长度、可读性或改写次数。
2. 在发布普通、协调与 deep 进度回包时，从该次不可变原报告提取链接。复用桌面已使用的 Markdown 解析器及其 GFM 裸链接扩展，支持 Markdown、引用式和裸 HTTP(S) 地址。忽略代码、图片、HTML、非 HTTP(S) 地址及含用户名/密码的 URL；不访问地址或补造来源。按首次出现顺序去重，保存前 32 个；其余仍在完整报告中。
3. 来源 URL 保留完整值；标签来自原链接文字，裸地址使用域名。标签最多 120 个 Unicode 码点，标签缩短不影响复制的 URL。`read_main_thread` 返回同一来源元数据，供后续任务按需读取。
4. 仅在最终截断路径，将 Markdown 链接替换为原标签、裸链接替换为域名，然后执行既有截断与提示。来源列表始终由原报告产生，不使用可能改写过的地址。原报告及 worker 上下文不修改。
5. 主会话在消息下方展示来源条目，复用现有 Markdown 的明确复制行为；完整 URL 用于复制和提示。仍遵守 ADR-0040 的本地窗口边界，不自动导航或加载远程内容。

## 后果

来源不会因正文改写或截断而丢失。协议校验、存储、普通回包、deep 回包、MCP 按需读取和桌面复制均需回归覆盖。旧记录不补写或迁移；字段缺省也用于没有来源的消息。
