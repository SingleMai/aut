# ADR-0064：主会话附件与成果快照

- 状态：已接受（用户确认文件输入、交付和历史版本范围）
- 日期：2026-11-23

## 背景

主会话需要支持拖入文件、粘贴截图、预览与移除草稿，并让 Bot 处理后交付可保存、可引用继续修改的文件。沿用现有 daemon 业务边界、主会话唯一入口和不可变报告身份；附件不成为新的路由器或会话入口。

## 决策

1. Core 的 `MessageFiles` 服务在数据目录 `files/<id>/` 保存内容和经 Schema 校验的清单。输入上传完成即形成快照，主会话仅引用服务生成的 ID；同名文件不覆盖。文件上限 20 MiB，每条消息最多 16 个附件，正文仍需明确任务说明。文件内容不进入分类器或默认上下文。
2. `MainThreadMessage` 和 `MainThreadExcerpt` 增加附件元数据；本地 API 上传、读取文件只使用 ID，不接受任意读取路径。入站先解析 ID，再原子保存消息与事件；幂等比较包括附件顺序和身份。引用回复保留被引用消息的文件，随新请求交接；历史消息不会被更新成最新版本。
3. 交接包在用户请求旁提供附件名称、类型和快照绝对路径。Bot 按需用 harness 文件/图片工具读取，修改前另存至工作目录。`read_main_thread` 同样返回这些引用；不新增 provider 专属分支或未经探针验证的原生输入字段。
4. 成果沿用 OpenMausBot 的 Markdown 文件链接方式：从原始成功报告中的本地链接/图片引用提取，回包改写前保存快照，正文仍经过既有门槛。只接受该执行会话工作目录内的普通文件，校验 realpath、句柄身份、大小与符号链接边界；不扫描整个目录。忽略代码、HTML、远程地址，拒绝隐藏文件/目录。快照 ID 绑定不可变报告事件与链接，因此重试不会重新读取已变化的原文件。无法保存的链接显示明确失败项，其他成果和文字仍能交付。
5. 每次新报告生成新快照，旧消息、文件和下载内容保持原版本。当前格式无迁移或旧字段兼容，既有消息缺省即无附件。未发送上传的租期与回收遵循 [ADR-0065](0065-file-lifecycle.md)，历史附件和成果不会自动删除。
6. 桌面沿用上游附件 chip 和预览交互；卡片显示文件类型图标、名称和大小，点击后在应用中预览文本/图片。其他格式在 macOS 使用系统 Quick Look；浏览器开发预览提供保存副本。另存为、Quick Look、Finder 定位均需用户点击，由 Electron main 按已保存 ID 解析，renderer 无权直接读取或打开任意路径。消息中的普通链接仍遵循 ADR-0040。末次回包截断将本地文件链接缩为标签，完整文件由独立卡片承载，避免半截路径占满正文。

## 后果与验证

文件传输采用有界 JSON/base64 经过现有鉴权 IPC/API，避免增加 renderer 凭据和第二种连接。该切片不处理目录上传、压缩包解包或 Office 在线编辑。验证输入快照、同名文件、引用续聊、回包改写、历史版本、无效链接、目录越界与幂等；使用隔离数据目录完成真实 Bot 文件处理和桌面交互验收。
