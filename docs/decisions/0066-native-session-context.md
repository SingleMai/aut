# ADR-0066：工作会话上下文由 Harness 管理

- 状态：已接受（用户确认复用 Agent Provider 的原生压缩能力）
- 日期：2026-11-24

## 背景

ADR-0006 与 ADR-0029 已约束主会话向工作会话的交接，但“长会话压缩”容易与交接片段预算、
回包改写及历史分页混淆。aut 使用完整的 Harness 会话，不直接维护模型请求的历史消息列表。

## 决策

1. 工作会话的模型上下文及原生压缩交给 Harness。aut 不另建摘要器、不按本地估算的 token
   数触发压缩、不把完整 transcript 重放给同一会话，也不覆盖用户的原生压缩配置。
2. HandoffBuilder 只准备本次交接：保留用户原话，按既有树选择有预算的主会话片段，附上引用和
   按需读取工具提示。片段成本是 UTF-8 字节数给出的保守上界，不代表会话上下文占用或模型窗口。
3. 原生上下文用量、压缩状态和手动压缩入口属于后续适配能力。必须先完成当前 CLI 的真实探针，
   再定义统一 Schema、capabilities 与桌面交互；不能把其他 Harness 的能力推断为通用能力。
4. 只读历史分页、ReplyGate 的独立 fork 改写继续保持各自职责，不以压缩名义删除主会话记录、
   改写持久化报告、清空待答问题或替换工作会话。现有无 fork 时的临时查询会话不受影响。

## 理由

复用 Harness 对模型窗口、工具历史和会话状态的处理，避免两套摘要同时改变上下文。
OpenMausBot 的 Codex 实现同样调用原生 `thread/compact/start`；这是接入参考，不能替代 aut 的协议探针。

## 后果与验证

本次只明确职责并整理交接片段的成本计算与模板渲染；不新增压缩接口或树外模型调用。
交接选择、预算边界、原话与附件保留、new/send 模板和决策日志仍由现有回归验证。
现行边界集中维护在 `docs/harness-adapters.md`，交接算法继续由 `docs/handoff.md` 说明。
