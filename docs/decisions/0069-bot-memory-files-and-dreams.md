# ADR-0069：文件记忆与默认定时整理

- 状态：已接受（继续落实 ADR-0068 及用户已确认的文件记忆方案）
- 日期：2026-11-24

## 背景

Claude / Codex 原生自动记忆已统一关闭。剩余能力是 bot 独立目录、工作会话读取、用户编辑与默认定时整理。
用户明确要求依托文件系统、不设计记忆数据库、版本或冲突协议，工作记录复用 Harness 原始会话。

## 决策

1. 记忆放在数据目录 `memory/<sha256(botId)>/`，与 workdir 分离；包含 `MEMORY.md`、`knowledge/`、`notes/`。
   API 校验 bot 归属与相对 Markdown 路径，不跟随符号链接。用户和 bot 仍可通过原生文件工具操作目录。
2. SessionSetup 在新建和重建会话时注入顶层记忆及目录说明；延续已存活会话不重放系统提示。
   顶层自动注入最多 8000 字符，超出时明确告知并提供完整文件路径，工作中按需读取最新文件。
   普通工作主要写各自会话的 notes，整理会话维护知识和顶层入口；用户明确要求记住或修正时可立即更新。
3. 每个 bot 自动拥有一个独立整理触发器，默认本地时区每天 03:00，用户可通过现有触发器配置暂停或改时间。
   系统仅补齐缺失计划，不重置用户设置。沿用现有 enabled 开关暂停系统计划；bot 移除后暂停计划并保留历史文件。
4. 复用 TriggerRegistry 的 occurrence 账本、Chief 声明式触发树、独立 Task/Session 与正常报告流程。
   bot 在 created/running/waiting_user/reporting 或有待执行队列时，整理 occurrence 保持 queued，空闲后重试。
   queued occurrence 在现有 12 小时窗口内可重新投递，start 的条件更新保证只启动一次；过期记录 missed。
   不阻止用户随后启动普通工作，不另建全局任务锁或冲突系统。
5. 整理仍使用本 bot 的 Harness/模型。通过现有任务列表与新增只读 `read_task_session` MCP 读取同 bot 的原生会话，
   可分页，跨 bot 读取拒绝。整理提示排除整理会话本身，优先最新明确指令，避免将旧推断循环强化。
6. 用户编辑、删除、清空及整理开始前，在 `memory-history/<sha256(botId)>/` 保存目录快照，最多保留 10 份。
   仅供审查，不增加版本比较、恢复合并、来源数据库或遗忘墓碑。删除的信息允许重新学习。
7. 桌面 Bot 页提供记忆文件列表与编辑器、清空、快照只读查看、整理计划开关和任务记录入口。
   不新增原生记忆来源选项或任意本地路径的 Electron 打开权限。

## 理由

文件是用户可以直接理解和修正的记忆载体。既有调度、任务和会话已经承载去重、执行和审查，
无需再为记忆引入另一套存储或后台模型调用。按会话写 notes 是提示词约定，不伪装为文件冲突保证。

## 后果

单文件编辑/读取上限 256 KiB，目录最多 512 个普通文件、16 MiB（包含原生工具写入的其他类型文件）；超限返回明确错误，不静默丢文件。
顶层注入预算不等于文件编辑上限。API 写入采用临时文件替换防止半写入，不提供 CAS/版本语义。
快照不跟随目录外链接；原生文件修改会在下次读取时出现，UI 支持主动刷新。
所有文件和会话归属是应用层约束，最高文件权限下不承诺操作系统级隔离。
