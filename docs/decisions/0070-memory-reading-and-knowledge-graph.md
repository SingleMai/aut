# ADR-0070：核心记忆阅读与文件知识图谱

- 状态：已接受（用户确认先接通实际使用链路，暂不引入剪枝）
- 日期：2026-11-24

## 背景

记忆编辑器把文件结构、编辑和维护操作平铺，用户难以看出 Bot 记住了什么。
用户确认以核心 Memory 为默认内容，知识库采用类似 LLM Wiki 的链接关系浏览，
通过真实工作与定时整理积累使用反馈。继续遵循文件系统记忆，不增加数据库或冲突协议。

## 决策

1. Memory 模块默认阅读渲染后的 `MEMORY.md`，显式进入编辑。核心记忆、知识库、笔记分入口；
   自动整理默认显示简短状态，计划管理、审查历史和删除/清空收在次级操作中。
2. 知识库提供图谱与可搜索列表。一个 `knowledge/` Markdown 文件是一个节点，
   文档中的有效相对 Markdown 链接是有向边。点击节点或正文中的内部链接阅读文档，突出直接关联。
   笔记和原始会话不混入知识图。文件仍是唯一事实来源，图按需从同一 Bot 的当前文件或选定快照重建。
3. 使用标准 Markdown 行内链接及引用式链接；路径相对于包含链接的文档，允许指向同一记忆目录内的
   `MEMORY.md`、`knowledge/` 和 `notes/`。图仅展示知识文件之间的边；代码、图片、外部 URL、越界路径不生成边。
   缺失目标作为断链提示，不能伪装成已有知识。标题取文档首个一级标题，缺少时使用文件名。
4. 工作和整理提示说明链接约定。整理会话在有事实依据时补充关联，拆分、合并或移动文件时修复相关链接，
   在核心 Memory 留简短的主题入口。没有依据的关联不补造，现有未链接文档仍可独立展示。
5. 本次不添加自动剪枝、使用热度或过期评分。更新时间仅表示文件修改时间。
   整理继续通过现有定时任务及独立会话运行，沿用目录快照与会话审查。

## 理由

阅读、沿链接查找、修改、整理后的回读组成最小使用闭环。图谱帮助理解文件关系，
不要求用户维护第二套数据，也不要求模型为了显示图谱额外推断关系。

## 后果

新增只读图谱 API 和对应 Schema；沿用 Bot 归属、路径校验、文件限额及安全 Markdown 边界。
首次建立关联前图可能较稀疏，应提供清楚的空态及列表回退。
原生文件修改通过刷新回读；不承诺文件监视或跨工具完整使用统计。
