# ADR-0075：模型接入融合到 Bot 配置

- 状态：已接受
- 日期：2026-11-25
- 后续：第 2、3 项的界面与探针范围由 [ADR-0076](0076-bot-model-picker-adapter-catalog.md) 更新。

## 背景

用户明确选择在 Bot 配置里完成模型接入，不接受独立的 AI 服务或 Agent 管理页面。
现有 Bot 已通过 modelSelection 引用执行实例和模型，但桌面将两者拆成全局实例表单与
Bot 内手填模型，暴露了不必要的配置层级。

## 决策

1. Bot 编辑器提供统一的「模型」选择。已保存的选择直接复用；可在原地读取执行电脑
   已有程序的模型配置，或输入自定义模型。模型名和接入来源同时展示，内部继续保留
   instanceId、model 和 effort，不迁移用户的 Provider、项目或已有 Bot 配置。
2. 接入细节属于 Bot 编辑器内的渐进展开内容，没有独立管理入口。首次接入或特殊启动
   参数也在此编辑；取消只丢弃草稿。默认提供现有 Codex 接入，不声称已经安装或登录。
   当前没有可用的原生登录 API，因此不提供虚假的应用内登录动作。
3. 为读取模型新增鉴权后的 POST /v1/bot-models/discover。输入为执行配置草稿和工作目录，
   只在当前执行主机启动有 Scope 和超时的只读探针，不创建会话或写原生配置。
   daemon 按已注册 reader 的支持能力委派；首个 reader 复用 Codex config/read 与
   model/list 协议。自定义 Provider 保留其已配置模型，不拿其他 Provider 的目录替代。
4. 保存接入使用 POST /v1/bot-models/connection：在 ConfigStore 的 mutation 锁内按
   显示名称、kind、command、args、env、authMethodIds 复用相同配置，否则追加新配置。不得覆盖
   已有实例，因此编辑一个 Bot 的接入不会改动其他 Bot 或已有任务引用的实例。
   此操作幂等地返回实际引用，随后沿用 Bot 和 MCP grant API 顺序保存。
   部分保存失败保留草稿和已保存 Bot 身份；尚未绑定 Bot 的接入可供重试复用。
5. 全局设置只保留设备连接和应用级协调配置。保存分类器时回读当前配置，保留所有接入，
   不使用打开设置页时的旧实例快照覆盖 Bot 编辑器新增的配置。

## 理由与后果

用户只管理 Bot，接入配置是实现细节。一个选择仍能精确定位程序与模型，并复用已有登录。
读取失败明确反馈，保留既有选择和手动输入能力；旧选择不因刷新目录被自动替换。
本轮不新增账号系统、CLI 安装器、OAuth 转发或多主机调度。

验收覆盖取消无写入、相同接入复用、修改不影响其他 Bot、失败后重试不重复创建、目录
读取不覆盖自定义 Provider、全局设置保存保留最新接入，以及 Bot 编辑器的键盘与窄屏操作。
