# ADR-0076：Bot 模型选择覆盖已接入程序

- 状态：已接受
- 日期：2026-11-26

## 背景

ADR-0075 将模型配置放入 Bot，但仍展示启动命令、环境变量等「连接细节」，且只有
Codex 能读取模型。用户明确要求移除这些字段，并在同一选择器切换所有已经适配的程序。
后端实际已实现 Codex、Claude Code 和 ACP；OpenCode 有完整回合样本，Grok 只有
握手与未登录边界样本，不应把它们都描述为已验证可用。

## 决策

1. Bot 编辑器只展示一个模型选择入口。弹层内可浏览不同程序及其模型；启动命令、
   参数、环境变量、协议类型、认证方法不进入 Bot 表单，也不另建 Agent 管理页。
   已有自定义接入按原名称保留，不复制或改写原生账号、Provider 和项目配置。
2. daemon 统一登记 adapter 工厂、模型 reader 与内置候选项；renderer 不按 kind 分支。
   GET /v1/bot-models/options 合并现有配置与 Codex、Claude Code、OpenCode、Grok
   候选，标记执行电脑上的程序检测结果、是否支持读取模型和验证范围。Grok 标为待验证；
   未完成探针的 Gemini/Qwen 不作为已支持的内置候选，已有 ACP 配置仍可显示。
   程序存在不代表已登录，更不代表模型调用已验证。
3. 选择器打开或浏览某一程序时读取模型。读取失败、未安装或不支持读取时给出具体状态；
   保留已保存的模型和自定义模型输入。晚到的响应不能覆盖用户选择、编辑或工作目录变化。
   浏览另一程序并不提交选择；点击模型才修改 Bot 草稿。取消不得保存配置。
4. Codex 继续使用 config/read 和 model/list。Claude 使用 stream-json 的
   control_request initialize 返回模型列表，禁用 hooks、MCP 和会话持久化，不发送 user
   frame。ACP 使用 initialize、必要的既有认证方法和 session/new 的 configOptions
   读取模型；不发送 prompt，不修改模型选项，声明 close 的程序会调用 session/close。
   ACP 可能保留空的原生会话，因此不再将整个发现 API 描述为「不创建原生会话」。
   所有探针使用 Scope、超时，错误只返回脱敏消息；模型列表不等于在线可用性测试。
5. 保存现有接入保留其准确 instanceId，不因同名/相同配置被换成另一个实例。
   内置候选仅在保存 Bot 时使用 ADR-0075 的幂等追加接口，再保存 modelSelection。
   不修改其他 Bot 或既有任务的选择；部分保存失败仍能重试。主助手的已配置模型也按同一
   adapter 登记表判断支持范围，不能因为默认发现探针仅支持 Codex 而拒绝 Claude/ACP。

## 理由与后果

用户在 Bot 中做一次模型选择即可，不需要管理实现层级。内部继续保留 adapter 与
执行实例以保证进程边界和已有配置兼容。本次不新增安装器、账号系统或登录代理。
增加真实 Claude 初始化模型投影、ACP 模型投影及回放测试；验收包括跨程序切换、
自定义接入保留、失败/迟到结果、取消无写入与窄屏键盘操作。
