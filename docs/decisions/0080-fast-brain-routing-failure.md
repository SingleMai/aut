# ADR-0080：主快脑的配置和消息分配失败

## 背景

主会话依赖快脑判断普通消息的去向。ADR-0079 把停用列在服务来源中，主服务缺失或请求失败时还会让用户手动选择任务。用户希望选好快脑后持续使用，调用失败时直接知道这条消息分配失败。

## 决策

1. 主快脑的服务来源为 Jev 官方或自定义兼容服务。首次尚未选择时显示「待配置」。设置只保存含主服务的配置；其他客户端保存执行电脑配置时，省略分类器字段会保留已有主备配置。原先没有该字段的数据仍可读取。
2. 用户可以显式添加或移除备用快脑。已选备用服务时仍遵循 ADR-0022 的共享时间预算。入站分类最终失败时终止本条决策，记录调用错误和失败结果，原消息留在主会话。主会话显示一条失败通知。缺少配置或服务拒绝密钥访问时提示检查快脑设置，临时故障提示稍后重新发送。
3. `classify.onError` 仍须显式声明。节点名表示按既定错误分支继续，`null` 表示以分类错误结束、没有决策输出。普通消息与引用回复使用后一种方式。分类成功但语义不清时沿用澄清，已绑定目标的卡片动作和后台任务沿用各自的处理路径。
4. 失败日志保存最终分类错误码。若 daemon 在日志落盘后、通知写入前重启，可按原事件 ID 补齐同一条通知。

## 理由与后果

一次服务故障不会改变用户的快脑选择。依赖分类的消息可得到明确结果，后续消息继续入队。沿用已有的决策日志、主会话通知和事件去重机制。该决策替代 ADR-0003、0045 中入站分类不可用时生成澄清卡的约定，以及 ADR-0079 中的主快脑停用入口。
