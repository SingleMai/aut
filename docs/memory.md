# Bot 记忆

长期记忆由 aut 统一管理，按 bot 隔离；不提供 Harness 原生记忆来源选择。
决策见 [ADR-0068](decisions/0068-aut-managed-bot-memory.md)、[ADR-0069](decisions/0069-bot-memory-files-and-dreams.md)
与 [ADR-0070](decisions/0070-memory-reading-and-knowledge-graph.md)。

## 文件与职责

- 每个 bot 拥有数据目录内 `memory/<sha256(botId)>/`，独立于 workdir。顶层 `MEMORY.md` 保存简短的核心记忆与目录入口。
  新建/重建工作会话自动注入前 8000 字符；超长时提示按完整路径读取。存活会话在需要时自行读取最新文件。
- `knowledge/` 保存可复用知识，bot 可以自行拆分、组合和组织文档，按需读取。
- `notes/` 保存工作中值得保留的发现。提示词约定按会话分文件，尽量减少同时重写同一内容。
- 工作原始记录直接复用 Harness 会话历史，不另建工作记录目录或记忆数据库。
- soul 继续定义角色与长期指令；记忆记录工作积累，二者分开维护。

用户可以查看、编辑和清空记忆文件。删除后的内容允许在未来重新学回；不建立禁止重新学习的标记。
首版不引入团队共享、版本检查、冲突合并或数据库级追溯；审查以整理会话及简单文件历史为基础。
编辑、删除、清空和整理前保存目录快照，放在 `memory-history/<sha256(botId)>/`，最多保留 10 份，只读查看。
用户 API 支持顶层 MEMORY.md 和 knowledge/、notes/ 下的 Markdown 文件；单文件 256 KiB、目录最多 512 文件/16 MiB。
此处的隔离是目录归属与加载规则；最高文件权限下不承诺操作系统级隔离。

## 阅读与知识关联

Memory 默认阅读核心记忆，显式进入编辑。知识库提供图谱和可搜索列表，选择节点后阅读正文与直接关联。
笔记保留独立入口；自动整理管理、审查历史和清空操作放在次级入口。

知识图按需从当前 Bot 的 `knowledge/` Markdown 文件生成，也可查看选定审查快照内的关系。
一个文件对应一个节点，首个一级标题作为名称（缺少时使用文件名），标准 Markdown 行内或引用式链接对应有向关系。
链接相对于当前文件，例如 `MEMORY.md` 中 `[发布流程](knowledge/release.md)`，
`knowledge/release.md` 中 `[环境配置](environment.md)`，嵌套目录中可用 `../` 返回上级，但不能离开 Bot 记忆目录。
正文可导航到同目录内的核心记忆、知识和笔记；图只纳入知识文件之间的关系。
代码和图片里的内容、外部 URL、越界路径不生成关系；缺失目标显示断链提示。
图是文件的派生视图，不另存知识数据库，不推断隐含语义关联。

工作中可以引用相关知识；整理时检查已有链接，补充有依据的关联，拆分、合并或移动文档时修复入口和反向引用。
没有关联的文档可以保留独立节点。不根据连接数或文件时间自动剪枝；本次不实现使用热度或过期评分。
原生文件修改通过主动刷新回读，更新时间不代表最后使用时间。

## 定时整理

“做梦”默认开启，复用现有定时机制，以本 bot 的 Harness / 模型运行独立的整理会话。
默认本地时区每天 03:00；已有/新建 bot 自动补齐计划，保留用户暂停和时间调整。
bot 忙碌时 occurrence 保持 queued，空闲后在既有 12 小时窗口内重试，超时记为 missed。
整理 notes 与已有知识，更新 knowledge 和顶层 MEMORY，保留该会话用于审查。
通过同 bot 的任务列表与只读 `read_task_session` 读取原始会话，整理会话不作为反复提炼的工作原料。
调度仍经既有 TriggerRegistry / Chief 执行链路，不在 chief 决策树外增加模型决策调用。
同一批到期事件先登记该 bot 的普通工作，再检查整理是否可启动；不限制不同 bot 并行。
整理启动后用户仍可发起普通工作，按会话写 notes 是提示词约定，不提供并发编辑冲突保证。

## Harness 边界

原生自动记忆关闭由 adapter 负责，覆盖新建、恢复、fork；具体参数与版本证据见
[Harness 适配层](harness-adapters.md#22-原生自动记忆)。用户的 CLI 全局配置、Provider 与认证保持原样。
关闭自动记忆不会关闭 `AGENTS.md` / `CLAUDE.md`、原生会话历史或上下文压缩，也不会清除已进入会话的内容。
原始会话能否完整读取取决于 adapter 能力：Codex 支持实时及冷历史读取，Claude 当前不支持冷历史读取。
原生历史不可用时整理会话使用已保存的任务报告和 notes，不假设缺失记录可恢复。
